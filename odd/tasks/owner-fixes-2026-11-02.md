# Owner fixes (2026-11-02, after end-to-end testing)

Objective: fix what the owner found while testing: partial catalog import, taller materials picker, a taller only offering WhatsApp, too many WhatsApp calls to action, and button colors by importance.
Branches: three parallel units, one PR each against main (F1 `fix/catalog-import-and-taller-materials`, F2 `fix/taller-turnos-and-public-ctas`, F3 `fix/button-colors`). Owner merges.

## Specs

S1. Import must load the whole catalog. Owner: "creo que al importar no se improtaron todos los productos". Evidence: after importing `docs/materials/catalogo-octubre-2026.csv` (95 products, 189 measures) the local DB holds 35 imported materials (Canastos, Bandejas, Espejos and 24 of the Lámparas), so the import stopped part-way. Cause found: `catalog-tools.ts` plans with one `repository.findActiveByName` per product and applies with one `repository.insert`/`update` per material, and every repository call opens its own DB session (`openSession` per call), so a 95-product import makes hundreds of connections in one Worker request and is cut off, leaving a partial, non-atomic import. Required: the import reads existing materials in one query (or a few batched ones) and writes all changes in ONE transaction, so it is all-or-nothing and completes for the October file in dev (`pnpm dev`, workerd) and production. Re-importing the same file after the fix must complete the partially imported state (idempotent upsert keeps working).

S2. Material picker with select all and search in "Nuevo taller". Owner: "al crear un nuevo taller tiene que estar la la opcion de selccionar todo o de buscar lo que se quiere incluir". The one-page "Nuevo taller" form (U2) lists materials as plain checkboxes; reuse the period-step picker from PR #194 (grouped by category, "Elegir todos" per category, search box) in the new-taller form, and make sure a global "Elegir todos" exists too.

S3. A taller that is open for enrollment must offer enrollment. Owner: "no entiendo por que taller de prueba 1 solo me deja hacer consultas por whatssap, si se supone que esta bierto y habilitado para inscribirse." Evidence: `taller-prueba-1` November period is open but its only turno ("Martes 12:15") was deactivated afterwards; the active turno "Turno tarde" was added after November opened, so it is only in December. The public reader selects November (`selectOffering`), filters the period's turnos to active ones, gets zero turnos, and the detail falls back to "Consultá por WhatsApp". Required: (a) public `selectOffering` skips open periods that have no active turno with capacity, so the next valid month (December) is offered; (b) adding a new turno to a taller also adds it, with its default capacity, to that taller's open months from the current month on (not past months); (c) the admin taller detail and Inicio "Hoy tenés que…" warn when an open month has no active turno ("Noviembre no tiene turnos activos: agregá uno") with a one-click fix that adds the active turnos to that month.

S4. Fewer WhatsApp calls to action; direct enrollment. Owner: "no tiene que haber tantos cta de consultas por whatssap, tiene que ser simple y directo la inscripcion." Today a taller detail page renders 7 WhatsApp links (per-turno "Consultá" links, the main action, booking summary, sticky bar, footer, header). Required: when enrollment is possible, the page has ONE primary "Inscribirme" action (plus its sticky mobile copy) and no per-turno WhatsApp links; at most one discreet secondary "¿Dudas? Escribinos" text link on the page body, besides the global header button and footer; the same rule on intensivo detail ("Reservar" primary). WhatsApp stays the primary action only when enrollment is not possible (no open month, paused).

S5. Button colors by importance, admin and public site. Owner: "la ui del panel hay que ajustarla, los botones de cada seccion, para selecionar una imagen, colocar colores segun importancia del boton (ej: rojo para boton eliminar, verde para agregar ) LO MISMO PARA EL SITIO PUBLICO." Required semantic variants with fixed colors used consistently: create/add/confirm-positive actions ("Agregar", "Nuevo …", "Crear", "Publicar", "Marcar pagado", "Recibido", "Subir foto"/"Elegir imagen") = green; delete/cancel/archive/destructive = red; the main next-step action that is neither (e.g. "Guardar", "Continuar") = brand primary; secondary/navigation = outlined neutral. The image picker ("Elegir imagen"/"Subir foto" in `ImageField` and the photo screens) must look like a real button, not a plain file input. Public site: positive commit actions ("Inscribirme", "Reservar", "Confirmar inscripción", "Agregar material") green; remove actions ("Quitar") red; WhatsApp links keep WhatsApp green only where they remain; secondary outlined. All pairs WCAG AA, asserted numerically.
