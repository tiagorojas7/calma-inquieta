## Global rules (apply to every task)

- **Tags.** `[BACK]` Claude Code (shared files, configs, CI, tooling, `src/modules`, `src/platform`, `src/composition`, `src/testing` except fixtures, `workers`, `public/media`, `docs/adr`, README, `openspec`). `[FRONT]` pi (`src/app/**` plus carve-outs `public/fonts/**`, `docs/design/**`, `src/testing/fixtures/**`). `[OWNER]` steps no agent can do. `odd/**` feature documents belong to whichever orchestrator runs that feature.
- **Commands.** Run everything through `corepack pnpm` (the global pnpm is 11). Focus a test with `corepack pnpm test <file>`, never `corepack pnpm test -- <file>`. A `*.ui.test.tsx` file runs in the `ui` project; every other `*.test.ts(x)` runs in `unit`.
- **Strict TDD.** Every behavior task is RED (write the test, run it, see it fail, record the failure), then GREEN (minimum code), then REFACTOR (tests stay green). Tests ship in the same commit as the behavior (`work-unit-commits`). Data-only or type-only files have no RED of their own; the task names the test that covers them. A task titled RED ends with the observed failure recorded in the PR notes.
- **Commits.** Conventional Commits only. NEVER a `Co-Authored-By` line or any AI attribution. One work unit per commit (behavior + its tests + its docs). Never shrink a diff by deleting comments, blank lines, docs or tests to fit the budget.
- **Local gate (end of every PR phase).** `corepack pnpm lint`, `corepack pnpm typecheck`, `corepack pnpm test`, `corepack pnpm format:check`, `corepack pnpm build`. All must exit 0.
- **ui test files.** Every `*.ui.test.tsx` file calls `expectNoAxeViolations` (from `src/testing/ui/axe.ts`). Page-level renders pass `{ page: true }`.
- **No literals bypassing tokens.** No `[#...]` arbitrary colors, no hex string literals, no `-[<length>]` arbitrary lengths in `src/app/ui/**/*.tsx` (DS2, §3.3). Attribute variants such as `data-[state=closed]:` are allowed.
- **PR chain context (every PR body).** Start, end, dependencies (merged PRs it needs), follow-ups, out of scope, and a dependency diagram with the current PR marked `📍`. Add the verification evidence (focused command output, RED evidence, ui suite time, line counts: production, tests, docs).
- **Size policy.** FRONT slices at most 400 production lines. If production alone passes 400, apply the slice's split rule, never ask first. If tests alone push the total past 400, label `size:exception` without asking. If a label does not exist on the remote, report it to the orchestrator; do not create labels.
- **Ownership seams.** FRONT never edits BACK files (including `src/modules/**`) outside the two carve-outs in DS13. If FRONT needs a content field, config option or dependency, it asks BACK for a small PR.
- **Items "verify in apply".** Verify against the installed versions and current docs; the design fixes behavior, not spelling. Record each result in the PR body.
- **Temporary states (do not run end-state spec checks before F7).** Between F2 and the page slices, `/`, `/quienes-somos` and `/contacto` answer 404 (accepted; recorded in the F2 and F3 PR bodies). The root 404 is English and unstyled until F3. The empty `sitemap.xml` urlset before F4 is harmless with the gate off.
